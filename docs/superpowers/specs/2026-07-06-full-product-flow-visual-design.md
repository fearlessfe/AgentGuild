# AgentGuild 全流程双主题视觉设计规格

## 1. 目标

本设计补齐 AgentGuild 从用户登录到任务审核闭环的产品界面，并形成可直接用于高保真设计和前端实现的规格。

交付范围：

- 1 张全流程总览。
- 10 个桌面 Web 关键页面。
- 每个关键页面提供深色与浅色版本，共 20 张高保真页面。
- 1 份组件、状态与响应式规则说明。
- 画布基准宽度为 1440px；不单独绘制移动端。

业务闭环：

1. 用户登录并进入 tenant 工作区。
2. 用户连接 Git 提供商，首期开放 GitHub。
3. 用户启用仓库并配置 GitHub Issues 同步规则。
4. 平台预览并自动同步任务。
5. Agent 领取、执行并提交任务。
6. 平台拉取 commit 并自动验证。
7. 人类审核、评分并接受或退回。
8. 平台回写 GitHub Issue，并更新声望、经验和审计记录。

## 2. 已确认决策

### 2.1 信息架构

采用“混合工作台”：

- 首次使用以分步引导为主，突出下一步和完成条件。
- 完成首次仓库同步后进入高密度日常工作台。
- 引导模式和日常模式共用一套导航、组件和主题 token。
- 用户可从帮助菜单重新打开引导，不重复创建连接或规则。

### 2.2 Git 提供商

- 界面使用通用“Git 提供商”概念。
- 首期只开放 GitHub，使用 GitHub App。
- GitLab 显示为不可用的后续能力，不设计虚假的可操作流程。
- 当前后端只提供 tenant 级 GitHub App 配置。仓库目录、Issue 同步规则和回写能力属于后续实现范围，设计中需标明新能力。

### 2.3 任务同步

采用“规则自动同步 + 预览 + 暂停 + 异常处理”：

- 人类配置仓库、标签、频率和默认策略。
- 平台或受信任系统身份根据规则创建正式任务。
- 人类不通过页面勾选 Issue 后直接发布正式任务。
- 同步预览区分新增、更新、忽略和冲突。
- 同步异常可以重试、忽略或暂停规则，并进入审计记录。

### 2.4 主题

- 深色和浅色使用相同布局、信息层级、组件尺寸和语义状态。
- 主题仅通过 token 切换，不维护两套页面结构。
- 深色强调低眩光和高密度运营。
- 浅色强调证据可读性、日间办公和分享。

## 3. 产品原则

### 3.1 Agent 操作，人类治理

人类页面允许：

- 登录与工作区选择。
- Git 提供商授权。
- 仓库和同步规则配置。
- 同步暂停、重试和异常治理。
- 查看任务、执行和提交事实。
- 行评论、评分、接受或退回。

人类页面不提供：

- 领取任务。
- 伪装成 Agent 发布正式任务。
- 手动填写 branch 或 commit SHA 替 Agent 提交。
- 绕过验证直接完成任务。

### 3.2 证据链贯穿

所有关键页面均可追溯：

`GitHub Issue → Task → Execution → Submission → Commit → Validation → Review → Outcome`

上下文栏至少保留当前工作区、仓库、Task ID、Execution、Commit、Agent Version 和状态中的适用项。

### 3.3 只展示服务端事实

- 不合成 Agent “完成百分比”。
- 执行进展以事件、阶段、检查数量、lease 时间和最近心跳表达。
- 成本明确区分 observed、self-reported 和 coverage。
- 同步和验证不展示无法证明的剩余时间。

## 4. 角色与责任线

### 4.1 人类治理

- 登录与工作区。
- 连接 Git 提供商。
- 启用仓库与同步规则。
- 审核任务并给出结论。

### 4.2 平台编排

- 扫描 GitHub Issues。
- 生成同步预览。
- 创建或更新任务。
- 刷新执行状态。
- 拉取 commit、diff 和 CI 结果。
- 运行验证并执行硬门槛。
- 回写 Issue、声望、经验和审计记录。

### 4.3 Agent 执行

- 发现并领取任务。
- 获取 lease、Git 凭证和 branch。
- 修改代码、测试和续租。
- 推送 commit 并提交 SHA。
- 根据审核意见返工并创建新 revision。

## 5. 全局产品框架

### 5.1 导航

左侧图标轨按以下顺序组织：

1. 首页/概览。
2. 仓库。
3. 任务。
4. 审核。
5. Agents。
6. 声望。
7. 设置。
8. 帮助。

顶部栏包含：

- AgentGuild 品牌。
- tenant/工作区切换器。
- 当前模块名称。
- 全局搜索与命令面板。
- 通知入口。
- 主题切换。
- 用户菜单。

上下文栏按当前页面显示：

- 仓库。
- Issue 或 MR/PR。
- Task ID。
- Execution。
- Commit。
- Agent Version。
- 同步、执行、验证或审核状态。
- 耗时和成本。

### 5.2 引导模式

首次登录且未完成仓库同步时进入 `/setup`。

五步引导：

1. 登录确认。
2. 连接 Git。
3. 选择仓库。
4. 配置并预览同步。
5. 完成首次同步。

完成条件：

- GitHub App 连接有效。
- 至少启用一个仓库。
- 至少保存一条有效同步规则。
- 至少一次同步运行成功。

空仓库或零匹配 Issue 可以保存配置，但不能自动标记 onboarding 完成。

### 5.3 日常模式

完成 onboarding 后默认进入 `/tasks`：

- 左侧为视图和状态聚合。
- 中间为任务列表或当前工作区。
- 右侧为选中任务的事实详情。
- 列表筛选、页签和选中项写入 URL。
- 同步与验证在后台运行，离开页面不会中断。

## 6. 十个关键页面

### 6.1 页面 01：登录

目标：安全进入工作区，并明确企业登录与本地开发登录的边界。

主要内容：

- AgentGuild 品牌与一句话价值说明。
- “使用企业 OIDC 登录”主操作。
- 本地开发登录折叠区，仅在服务端启用时显示。
- 安全说明：身份来自组织、会话受保护、不会在页面保存 Git 私钥。
- 登录失败、会话过期和服务不可用状态。

交互：

- OIDC 主操作跳转 `/oauth/oidc/login`。
- 本地登录提交密码但不回显，不提供记住密码。
- 登录成功回到原始深链；无深链时进入 `/setup` 或 `/tasks`。

### 6.2 页面 02：首次引导

目标：让新用户知道还差什么才能跑通第一个任务。

主要内容：

- 五步进度。
- 当前步骤标题、说明和完成条件。
- 已完成步骤摘要。
- 预计所需权限，不显示虚假的预计耗时。
- “稍后继续”与“继续”。

交互：

- 仅允许跳回已完成步骤。
- 未完成步骤可保存草稿。
- 页面刷新后从服务端事实恢复进度。

### 6.3 页面 03：Git 接入

目标：安装并验证 GitHub App。

主要内容：

- GitHub 可用卡片。
- GitLab “即将支持”卡片。
- GitHub App 所需权限：Contents 只读、Issues 读写、Checks 只读、Metadata 只读。
- App ID、Installation ID、Base URL 等非敏感配置摘要。
- 私钥输入区只用于提交，不回显完整内容。
- 连接检测结果和最近检测时间。

交互：

- 安装或连接 GitHub App。
- 检测连接。
- 更新配置。
- 删除配置时二次确认并列出受影响仓库。

### 6.4 页面 04：仓库与同步规则

目标：选择可治理的仓库，并配置 Issue 到 Task 的自动同步。

主要内容：

- 仓库搜索和多选列表。
- 默认分支、可见性、安装权限和最后活动时间。
- 每仓库启用状态。
- 规则构建器：
  - 包含/排除标签。
  - Issue 状态。
  - 任务类型映射。
  - 默认优先级、难度和 deadline 策略。
  - 同步频率。
  - 重复项策略。
- 规则摘要自然语言预览。

交互：

- 保存草稿。
- 运行预览。
- 启用、暂停或恢复规则。
- 危险变更确认影响范围。

### 6.5 页面 05：同步结果

目标：解释一次同步做了什么，为什么。

主要内容：

- 同步批次 ID、触发方式、开始/结束时间。
- 新增、更新、忽略、冲突和失败数量。
- Issue 与 Task 的对应列表。
- 忽略或冲突原因。
- 最近成功时间和下一次计划时间。
- 审计主体：用户配置、系统运行或管理员重试。

交互：

- 按结果类型筛选。
- 重试失败项。
- 忽略确认后的冲突。
- 暂停规则。
- 打开对应 Issue 或 Task。

### 6.6 页面 06：任务中心

目标：高密度观察全部任务和同步来源。

主要内容：

- 全部、待领取、进行中、待审核、已完成、异常页签。
- 仓库、类型、Agent、来源、同步状态和时间筛选。
- 分组任务列表。
- 任务来源：Agent API、GitHub Issue 同步或评测。
- 右侧详情：目标、验收条件、仓库、来源、执行状态、deadline。

交互：

- 页面不提供领取或人工提交。
- 支持复制 Task ID、查看 API 请求、打开 Issue。
- 当前筛选和选中任务可深链分享。

### 6.7 页面 07：执行详情

目标：理解 Agent 当前在做什么及其可验证事实。

主要内容：

- Agent 与不可变 Agent Version。
- lease 剩余时间、最近心跳。
- branch、base commit 和 repo scope。
- 时间线：领取、凭证签发、心跳、活动摘要、推送、提交。
- 公开检查数量、最近事件和成本覆盖。
- revision 历史。

交互：

- 展开事件详情。
- 复制诊断信息。
- 查看 commit 或 branch。
- 人类不能暂停、续租或替 Agent 提交。

### 6.8 页面 08：提交验证

目标：验证 Git 事实和自动检查，并给出可操作诊断。

主要内容：

- repo、branch、base commit、head commit。
- Commit 是否存在、是否位于 branch、base 是否为祖先。
- Build、公开测试、隐藏测试、安全扫描和范围检查。
- 变更文件、增删行和耗时。
- 验证 job 次数、lease 和最近错误。

交互：

- 后台自动刷新。
- 失败项可复制为 Agent 可处理的诊断摘要。
- 管理员只可重试平台失败，不可把代码失败标记为通过。

### 6.9 页面 09：审核工作台

目标：证据优先地完成代码审核和评分。

主要内容：

- 顶部验收摘要和自动检查。
- 文件树。
- unified/split Diff。
- 行级评论和 revision 定位。
- Rubric 评分、总分和评审备注。
- 退回修改与通过并评分。

硬门槛：

- Build、核心公开测试或安全硬门槛失败时禁用“通过并评分”。
- 页面明确列出阻塞原因。
- 退回修改保留评论、草稿评分和 revision 证据。

### 6.10 页面 10：结果闭环

目标：让用户看到审核结论造成的系统变化。

通过状态：

- Task 与 Execution 完成。
- GitHub Issue 回写完成或显示回写失败。
- 声望投影变化。
- 经验候选是否生成。
- 审计事件。

返工状态：

- 当前 revision，以及“Agent 尚未提交新 revision”的明确状态。
- 待处理评论列表。
- Agent 自动返工状态。
- 重新验证入口仅由提交触发，不提供人工“完成返工”。

## 7. 视觉系统

### 7.1 共用语义

字体：

- 中文 UI 使用系统无衬线字体。
- 代码、SHA、Task ID 和数值使用等宽字体。

密度：

- 桌面列表行高 40–44px。
- 页面主间距采用 4px 基数。
- 大容器圆角 8–12px；不用大面积胶囊按钮。

状态色：

- 主操作/当前选择：cyan 或可访问蓝。
- 成功：green。
- 等待/警告：amber。
- 失败/危险：red。
- 中性：gray。

状态必须同时使用文字或图标，不只依赖颜色。

### 7.2 深色主题

- 页面背景：近黑蓝灰。
- 卡片背景：比页面背景高一个层级。
- 边界：低对比冷灰。
- 主要文字：浅灰白。
- Diff 红绿背景降低饱和度，保证代码文本可读。
- 适合长时间查看执行与审核。

### 7.3 浅色主题

- 页面背景：极浅冷灰。
- 卡片背景：白色。
- 边界：中性浅灰。
- 主要文字：深蓝灰。
- 证据链接使用可访问蓝。
- Diff 使用低饱和浅红/浅绿。

### 7.4 主题行为

- 用户选择持久化。
- 未选择时跟随系统。
- 主题切换不丢失路由、筛选、表单草稿或滚动定位。
- 设计稿不得通过改变布局来“适配”主题。

## 8. 状态、错误与安全反馈

### 8.1 加载

- 保留页面框架，局部使用 skeleton。
- 同步和验证显示阶段名称、开始时间和最近事件。
- 不展示无法计算的剩余时间。

### 8.2 空状态

必须区分：

- 未连接 Git。
- 未启用仓库。
- 规则无匹配。
- 当前筛选无结果。
- 暂无待审核任务。

每种空状态只给一个最相关的下一步。

### 8.3 同步冲突

展示：

- GitHub Issue。
- 已存在 Task。
- 冲突字段。
- 规则版本。
- 最后成功时间。

可用动作：

- 重试。
- 忽略本项。
- 暂停规则。

不允许在冲突页人工编辑正式 Task 内容。

### 8.4 验证失败

错误按以下类别分组：

- Commit 不存在。
- Branch 不匹配。
- Base 不是祖先。
- CI 或测试失败。
- 安全硬门槛失败。
- 平台临时故障。

只有平台临时故障提供人工重试。

### 8.5 权限失效

GitHub App 被卸载或权限收窄时：

- 全局告警列出受影响仓库。
- 自动暂停相关同步。
- 历史 Task、Submission、Diff 和 Review 保持可读。
- 提供重新授权入口。

### 8.6 秘密处理

- 私钥和 token 不进入示例数据、页面日志、截图或设计稿。
- 私钥提交后只显示“已配置”和更新时间。
- Activation Token 若出现在其他页面，继续遵循只显示一次原则。

## 9. 路由与状态保持

建议路由：

- `/login`
- `/setup`
- `/settings/git`
- `/repositories`
- `/repositories/:repoId/sync-rules/:ruleId`
- `/sync-runs/:runId`
- `/tasks`
- `/tasks/:taskId`
- `/executions/:executionId`
- `/submissions/:submissionId/validation`
- `/reviews/:reviewId`
- `/tasks/:taskId/outcome`

规则：

- 任务列表筛选写入 query string。
- 选中 Task、Execution、Submission 和 Review 写入路径。
- 刷新、后退、前进和复制链接后状态可恢复。
- 表单草稿在路由切换前提示保存或放弃。

## 10. 响应式规则

### 10.1 1280px 及以上

- 完整图标轨。
- 列表、主内容、详情三栏。
- 审核页保留文件树、Diff 和评分三栏。

### 10.2 960–1279px

- 导航保持图标轨。
- 右侧详情改为可固定抽屉。
- 上下文栏允许横向滚动。
- 审核评分栏改为可固定抽屉。

### 10.3 720–959px

- 单主栏。
- 列表和详情通过路由切换。
- 审核默认 unified Diff。
- 评分使用底部抽屉。
- 不隐藏关键状态，只调整呈现位置。

低于 720px 不在本次高保真设计范围内，但实现不得阻止基本读取。

## 11. 可访问性

- 正文和关键控件达到 WCAG AA 对比度。
- 可操作元素有明确焦点样式。
- 完整键盘 Tab 顺序。
- 命令面板支持 `⌘K`/`Ctrl+K`。
- 图标按钮提供可访问名称。
- 错误与状态不只靠颜色区分。
- Diff 与评分控件支持键盘操作。

## 13. 验收标准

### 13.1 流程完整性

- 能从登录顺序走到 Git 接入、仓库启用、任务同步、Agent 执行、自动验证、人工审核和结果闭环。
- 通过与返工两条分支均有明确去向。
- Issue、Task、Execution、Submission、Commit 和 Review 可追溯。

### 13.2 角色边界

- 人类页面不存在领取、替 Agent 提交或绕过验证完成任务的入口。
- 同步规则由人类配置，正式任务由平台或 Agent 创建。
- 管理操作和 Agent 操作在文案、按钮和权限上可区分。

### 13.3 双主题

- 10 个关键页面各有深色和浅色版本。
- 两个主题结构一致。
- 语义状态和 Diff 在两个主题中均清晰可读。

### 13.4 状态覆盖

- 登录失败。
- Git 连接失败。
- 仓库为空。
- 规则无匹配。
- 同步冲突。
- 执行中。
- 验证失败。
- 审核硬门槛。
- 通过。
- 返工。
- GitHub 回写失败。

### 13.5 视觉与交互 QA

- 检查宽度：1440、1280、1024、768。
- 检查主题切换不改变信息架构。
- 检查刷新、后退、前进和深链恢复。
- 检查异步完成后的通知与页面刷新。
- 检查敏感数据未出现在设计稿。

## 14. 与当前实现的关系

可以直接复用或演进：

- `/login` 与 OIDC/本地登录入口。
- `/tasks`、`/tasks/:taskId`。
- `/reviews/:reviewId`。
- `/agents`、Agent Version、经验、评测和声望能力。
- tenant 级 GitHub App 后端配置。
- 任务、Execution、Submission、Validation 和 Review 领域数据。

需要新增或扩展：

- 前端 Git 设置入口。
- 仓库目录和启用状态。
- GitHub Issues 同步规则。
- 同步预览、运行记录和冲突治理。
- Issue 与 Task 映射。
- 审核结果回写 GitHub Issue。
- onboarding 完成状态。
- 全局主题 token 与持久化。
- 新的全局导航和上下文栏。

这些新增能力必须在实施计划中拆分为独立、可验证的增量，不能把视觉稿中的未来能力误认为当前后端已支持。

## 15. 接口适配矩阵

高保真稿必须标注每个页面所依赖能力的接口状态。状态分为：

- **可用**：当前 REST 路由和前端客户端均可直接支持。
- **后端可用**：REST 路由存在，但前端客户端或页面尚未接入。
- **部分可用**：核心资源存在，但页面所需字段、列表或操作不完整。
- **待新增**：当前无对应领域能力或 REST 路由。
- **需修正**：已有路由的认证方式或契约与人类 Web 流程不匹配。

| 页面 | 当前接口 | 状态 | 设计约束 |
|---|---|---|---|
| 登录 | `GET /oauth/oidc/login`、`GET /oauth/oidc/callback`、`POST /oauth/local/login` | 可用 | 本地登录仅在服务端启用时显示；`/oauth/local/login` 需补入 OpenAPI。 |
| 首次引导 | 无 onboarding 状态接口 | 待新增 | 设计稿将完成状态标记为规划能力，不假设前端本地状态等同于服务端事实。 |
| Git 接入 | `GET/POST/DELETE /v1/github-app` | 后端可用 | 可设计查看、保存和删除；“检测连接”需要新增接口；三条路由需补入 OpenAPI。 |
| 仓库目录 | 无安装仓库列表或仓库启用接口 | 待新增 | 仓库搜索、选择、默认分支和权限状态均标记为规划能力。 |
| 同步规则 | 无规则 CRUD、预览、启停接口 | 待新增 | 不把保存、预览或启停按钮标为当前可用。 |
| 同步运行 | 无 sync run、结果列表、冲突处理接口 | 待新增 | 新增/更新/忽略/冲突、重试和审计均为规划能力。 |
| 任务中心 | `GET /v1/tasks`、`GET /v1/tasks/{id}` | 可用 | 当前可展示任务事实；来源、Issue 链接、同步状态和同步批次字段需扩展。 |
| 执行详情 | `GET /v1/executions/{id}` | 部分可用 | 当前可展示 lease、状态、stage、progress 与成本；完整事件时间线和 revision 列表需新增查询。设计仍不把 progress 作为可靠完成率。 |
| 提交摘要 | `GET /v1/submissions/{id}`、`GET /v1/submissions/{id}/diff` | 后端可用 | 前端已有 Diff 接入；Submission 详情页和客户端需补齐。 |
| 验证详情 | Submission 仅返回 `validation_job_id`；无 validation job 查询路由 | 部分可用 | 检查步骤、attempt、lease 和日志详情需要新增只读接口，例如 `GET /v1/submissions/{id}/validation`。 |
| 审核读取 | `GET /v1/reviews/{id}`、`GET /v1/rubrics/active` | 可用 | 可直接支撑审核详情与 Rubric。 |
| 创建审核 | `POST /v1/submissions/{id}/reviews` | 后端可用 | session-only，符合人类创建审核语义；前端未提供显式入口。 |
| 审核评论/结论 | `POST /v1/reviews/{id}/comments`、`POST /v1/reviews/{id}/decision` | 需修正 | 当前路由使用 bearer-only `authenticate`，与人类 Web 审核不匹配；应支持 session 人类身份，同时保留 tenant 与权限校验。 |
| 结果闭环 | `GET /v1/reputation`，Agent 版本/经验/评测接口 | 部分可用 | 声望和经验可查询；Task outcome 聚合、Issue 回写状态和审计时间线需新增。 |
| 主题偏好 | 无服务端接口 | 部分可用 | 首期可使用浏览器持久化；若要求跨设备同步再新增用户偏好接口。 |

### 15.1 契约一致性要求

- `backend/internal/transport/rest/openapi.yaml` 当前只覆盖到 Execution 路由，未完整描述 Submission、Review、GitHub App、Agent Version、Experience、Evaluation 和 Reputation 等已存在路由。
- 在实现任何新增页面前，先补齐已存在 REST 路由的 OpenAPI 契约，并用契约测试防止再次漂移。
- 设计稿中的字段名称优先使用真实响应字段；规划字段使用 `planned` 注释，不伪装成现有响应。
- 人类页面的所有写操作必须使用 session 认证；Agent 的领取、执行、凭证和提交继续使用 bearer token。
- 新增同步写接口必须支持 `Idempotency-Key`，并在错误态设计中使用现有 `domain.Error` 语义。

### 15.2 高保真稿标注规则

每张页面稿在开发说明区使用以下标记：

- `API · available`：当前接口可直接支撑。
- `API · partial`：当前接口只能支撑部分信息。
- `API · planned`：需要新增后端能力。
- `API · auth fix`：接口存在，但认证或授权需先修正。

这些标记只出现在设计说明和交付标注层，不出现在最终用户界面。
