# Brainstorm Summary

- Change: improve-console-ui-ux
- Date: 2026-07-09

## Confirmed Facts

- The change is scoped to frontend console UI/UX quality and does not change backend APIs, database schema, or domain state machines.
- Primary UX risks are review diff readability, mobile task/agent list clipping, inconsistent structural icons, undersized mobile controls, and sparse feedback states.
- OpenSpec artifacts are complete and validated. The design handoff was generated by `comet-handoff.sh`.
- Mobile review should default to Unified mode while preserving mode controls.
- Mobile task and agent lists should use compact cards as the primary responsive presentation.
- `lucide-react` is the preferred SVG icon dependency for this React web frontend.

## Candidate Approaches

### Approach A: Minimal CSS Stabilization

Fix diff wrapping, add scroll wrappers, increase mobile hit targets, and replace the most visible icons. This is fastest but leaves task and agent mobile lists feeling like desktop tables compressed into a phone.

### Approach B: Focused Workbench UX Pass

Implement targeted component and CSS changes for the affected routes: readable diff behavior, mobile cards for task/agent lists, SVG shell/icons, breakpoint-scoped hit targets, and targeted Playwright checks. This best matches the confirmed scope.

### Approach C: Broader Design System Refactor

Refactor shell, UI primitives, list components, loading states, and route layouts into a more formal design system. This may produce a cleaner long-term foundation but is larger than this change and risks delaying the core fixes.

## Recommended Technical Plan

Use Approach B. Keep desktop density intact, improve mobile behavior at breakpoints, and avoid broad redesign. Implement verification-first checks where practical so the known regressions are protected.

## Key Trade-offs And Risks

- Adding `lucide-react` adds a dependency, mitigated by tree-shaken named imports.
- Mobile cards duplicate some table presentation logic, mitigated by sharing source data and keeping desktop tables unchanged.
- Diff horizontal scrolling can be awkward on mobile, mitigated by defaulting mobile review to Unified mode.
- CSS primitive changes can affect legacy screens, mitigated by scoping larger targets to mobile breakpoints and verifying core routes.

## Testing Strategy

- Add Playwright checks for review diff readability on desktop and 375px mobile.
- Add mobile checks for task and agent list core information visibility.
- Assert no page-level horizontal overflow on key mobile routes.
- Run frontend build, unit tests, and targeted Playwright specs.
- Inspect screenshots for task, agent, and review routes after implementation.

## Spec Patch

No additional spec patch is currently required. The accepted review refinements have already been applied to the OpenSpec delta spec and tasks.
